# Capital plan

This lane drains durable knowledge debt from memories, rules, agents, and
briefs. After chat selection, apply autonomously; draft exact diffs first but
do not re-ask per edit.

## Candidate gate

Mine preferences/friction, duplicate procedures, worst repeated sessions, and
already-captured knowledge across every inventory evidence lane. Logs and
conversations: **last 30 days only** (same lookback as
`references/inventory-and-dashboard.md`).

Promote new standing behavior only with recurrence: at least two sessions,
two repositories, a clear degraded-report repeat, or a memory already written
as recurring/encodeable operational behavior. A first sighting goes to
`memory/WATCH.md`, a waiting room that later graduates or retires.

Every candidate names target file, evidence, exact diff, and kind:

| Kind | Resolution |
| --- | --- |
| PROMOTE | Encode durably, verify, then delete source memory |
| RETIRE | Prove captured/dead/superseded, then delete |
| PEEL | Remove config only when unused and duplicated by a better owner |
| MERGE / RELABEL | Consolidate overlap; selected skill bodies defer to their gauntlet |
| PREFERENCE | Repeated correction into global brief or rule |
| KEEP | Report live external/in-flight state; not an apply failure |

Tier safety before productivity before preference. Do not manufacture config
for one-offs or treat WATCH as permanent storage.

## Apply

1. Confirm immutable copies for every target.
2. Apply selected candidates in dependency order: encode before delete, merge
   before peeling a loser.
3. Verify each PROMOTE edit before deleting its source; failed edit means source
   remains and candidate is blocked.
4. Require grep/evidence proof before RETIRE.
5. Reconcile memory index/WATCH and append every terminal outcome to
   `capital/apply-log.md`, state, and dashboard.
6. Continue unaffected candidates when one blocks.

Landing zones include canonical dotagents rules, brief, guards, hooks,
permissions, gate library, and selected skill bodies; child-repo knowledge
lands in that repo’s `AGENTS.md` or owned config. Never author `CLAUDE.md`.
Prefer child config until recurrence across repositories justifies global.

Repository guards still bind and no repository is pushed or merged here.
